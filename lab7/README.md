## О проекте

В [лабораторной № 6] сервер принимал HTTP-запрос и возвращал результат конвертации в JSON. В этой работе сервер также отвечает в JSON, но теперь сохраняет данные между запросами и после перезапуска. На примере заказов можно выполнить все четыре CRUD-операции: создать запись, прочитать список, изменить статус и удалить заказ.

## Используемые технологии

- **Python 3.10+ и FastAPI** — серверная часть на том же стеке, что и в лабораторной № 6. Pydantic проверяет поля запроса, Uvicorn запускает приложение.
- **sqlite3** — модуль стандартной библиотеки Python для выполнения SQL-запросов.
- **SQLite** — хранит таблицу `orders` в одном файле. Устанавливать отдельный сервер базы данных не нужно.

## Подготовка и запуск

В VS Code откройте папку `lab7` и создайте терминал (**Терминал → Создать терминал**). При первом запуске подготовьте окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запустите сервер:

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --port 3000 --reload
```

Откройте <http://127.0.0.1:3000/docs>. На этой странице можно выбрать маршрут, нажать **Try it out**, ввести данные и выполнить запрос кнопкой **Execute**. Список заказов доступен по адресу <http://127.0.0.1:3000/api/orders>. Если база ещё не существует, сервер создаст файл `orders.sqlite` и пустую таблицу. Для остановки нажмите `Ctrl+C`. При следующем запуске достаточно повторить команду Uvicorn: существующие заказы сохранятся.

### Если запуск не удался

- **`python` не найден** — установите Python 3.10+ и откройте новый терминал.
- **Не найден `main` или модуль `uvicorn`** — перейдите в папку `lab7` и проверьте, что зависимости установлены в её `.venv`. Активировать окружение для команд выше не нужно.
- **Порт 3000 занят** — если сервер уже запущен в другом терминале, используйте его либо остановите через `Ctrl+C` перед повторным запуском.

### Проверка

Оставьте сервер работающим и откройте второй терминал PowerShell. Создайте заказ без поля `status`:

```powershell
$url = 'http://127.0.0.1:3000/api/orders'
$order = Invoke-RestMethod -Method Post -Uri $url -ContentType 'application/json; charset=utf-8' -Body '{"customer_name":"Анна","total_amount":1250.50}'
$order
```

Пример ответа (значение `id` назначает SQLite):

```json
{"id":1,"customer_name":"Анна","total_amount":1250.5,"status":"new"}
```

Смените статус, проверьте фильтр и удалите именно созданный заказ:

```powershell
Invoke-RestMethod -Method Patch -Uri "$url/$($order.id)" -ContentType 'application/json' -Body '{"status":"paid"}'
Invoke-RestMethod -Uri "${url}?status=paid"
Invoke-RestMethod -Method Delete -Uri "$url/$($order.id)"
Invoke-RestMethod -Uri $url
```

Если перед удалением отправить в `PATCH` тело `{"status":"cancelled"}`, сервер вернёт `400`, а заказ останется в статусе `paid`. Успешное удаление даёт ответ `204` без тела.

Для автоматической проверки выполните `.\.venv\Scripts\python.exe -m unittest` из папки `lab7`. Тест использует отдельную временную базу SQLite: рабочие заказы не изменятся.

## Как работает приложение

1. При запуске сервер открывает SQLite и создаёт таблицу `orders`, если её ещё нет.
2. FastAPI проверяет данные запроса. Имя заказчика не должно быть пустым, `total_amount` должно быть числом не меньше нуля, а `status` — одним из значений `new`, `paid`, `shipped`, `delivered`.
3. Функции в [orders.py](./orders.py) выполняют `INSERT`, `SELECT`, `UPDATE` или `DELETE`. Значения передаются как параметры SQL-запросов. Для фильтрации используется условие `WHERE status = ?`.
4. Сервер возвращает заказ, список заказов или код результата. Доступ к базе идёт через API, браузер не открывает файл SQLite напрямую.

## API

| Метод и путь | Назначение | Успешный ответ |
|---|---|---|
| `GET /api/orders` | Показать все заказы в порядке `id`. | `200`, массив |
| `GET /api/orders?status=paid` | Показать только оплаченные заказы. | `200`, массив |
| `POST /api/orders` | Создать заказ: обязательны `customer_name` и `total_amount`. Без `status` будет установлен `new`. | `201`, созданный заказ |
| `PATCH /api/orders/{id}` | Изменить только статус. Пример тела: `{"status":"shipped"}`. | `200`, обновлённый заказ |
| `DELETE /api/orders/{id}` | Удалить заказ. | `204`, без тела |

`POST` и `PATCH` принимают `Content-Type: application/json`. Некорректная сумма или неизвестный статус дают `400`. Если при изменении или удалении заказ не найден, ответ — `404`.
